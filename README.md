# WordChainAI

---

# 프로젝트 개요

WordChainAI는 OpenAI Responses API를 활용한 콘솔 기반 끝말잇기 게임입니다.

본 프로젝트는 단순히 OpenAI API를 호출하는 것에 그치지 않고, Prompt Engineering, JSON 기반 응답 처리, LLM 출력 검증 및 게임 상태 관리를 직접 구현하는 것을 목표로 개발했습니다.

특히 AI가 생성한 결과를 그대로 사용하는 대신, JSON 형식 검증과 게임 규칙 검증을 거친 뒤에만 게임 로직에 반영하도록 설계하여 LLM 기반 애플리케이션의 안정성을 높이고자 했습니다.

* 개발 형태: Python 기반 콘솔 애플리케이션
* 개발 인원: 1인
* 개발 기간: 2일

---

## 게임 규칙

* 표준국어대사전에 등재된 일반 명사만 사용할 수 있습니다.
* 이미 사용한 단어는 다시 사용할 수 없습니다.
* 두음법칙을 적용합니다.
* 게임 시작 시 한방단어 허용 여부를 선택할 수 있으며, 해당 옵션은 사용자와 AI 모두에게 동일하게 적용됩니다.
 * 한방단어 허용 시에도 11번째 단어부터 사용할 수 있습니다.
* 사용자와 AI 모두 10초 이내에 응답해야 합니다.
* 잘못된 단어 입력, 시간 초과, AI 응답 오류는 모두 실수로 처리됩니다.
* 실수는 최대 3회까지 허용되며, 4번째 실수 발생 시 패배합니다.

# 시스템 설계

## 모듈 구조

| 파일 | 역할 |
| ------------------ | ----------------------------------------- |
| `main.py` | 프로그램의 진입점(Entry Point)입니다. |

| `utils.py` | 사용자 입력 시간 제한 등 공통 기능을 제공합니다. |

## 모듈 간 상호작용

```text
             main.py
                │
                ▼
             game.py
      ┌────────┼─────────┐
      ▼        ▼         ▼
 state.py validator.py openai_client.py
                           │
                           ▼
                       prompt.py
```

`game.py`는 게임 진행만 담당하며, 검증은 `validator.py`, AI와의 통신은 `openai_client.py`, 상태 관리는 `state.py`로 분리하여 각 모듈이 하나의 책임만 갖도록 설계했습니다.

# 구현 내용

## 게임 상태 관리

게임의 모든 상태는 `GameState` 객체 하나에서 관리합니다.

* 현재 단어
* 사용된 단어 목록
* 현재 체인 수
* 사용자 및 AI 실수 횟수
* 한방단어 허용 여부
* 게임 종료 여부
* 승자

이를 통해 게임 진행 중 필요한 모든 정보를 하나의 객체에서 일관성 있게 관리하도록 구성했습니다.

---

## 규칙 검증

모든 입력은 `Validator`를 통해 아래 순서대로 검증합니다.

1. 빈 문자열 여부
2. 끝말잇기 규칙
3. 두음법칙
4. 중복 단어
5. 표준국어대사전 일반 명사 여부
6. 한방단어 여부
7. 게임 옵션 적용

사용자와 AI 모두 동일한 검증 절차를 거치므로, AI 역시 게임 규칙을 위반할 수 있으며 실수로 처리됩니다.

---

## OpenAI 응답 처리

AI는 자연어가 아닌 JSON 객체를 반환하도록 설계했습니다.

생성된 응답은 아래 과정을 거쳐 게임에 반영됩니다.

1. JSON 파싱
2. JSON 객체 여부 확인
3. 필수 필드 존재 여부 확인
4. 게임 규칙 검증
5. 게임 상태 반영

이를 통해 JSON 형식 오류나 LLM 환각으로 인한 잘못된 응답이 게임 로직에 직접 영향을 주지 않도록 했습니다.

---

## 사용자 인터페이스

콘솔 환경에서도 게임의 진행 상황을 쉽게 파악할 수 있도록 UI를 구성했습니다.

* 시작 화면 및 규칙 안내
* 한방단어 허용 여부 선택
* 현재 체인 및 현재 단어 표시
* AI 차례 안내
* 실수 발생 화면
* 게임 종료 화면

---

## 예외 처리

다음과 같은 예외 상황을 처리하도록 구현했습니다.

* 사용자 입력 시간 초과
* 빈 문자열 입력
* OpenAI API 호출 실패
* JSON 파싱 실패
* JSON 형식 오류
* 존재하지 않는 단어
* 중복 단어
* 게임 규칙 위반

# 기술적 고민 및 개선점

## LLM 출력의 신뢰성

LLM은 항상 올바른 형식으로 응답한다고 보장할 수 없습니다.

따라서 AI의 응답을 그대로 사용하는 대신 JSON 파싱과 필수 필드 검증을 수행한 뒤, 다시 게임 규칙 검증을 거쳐 게임에 반영하도록 구현했습니다.

---

## AI와 사용자의 동일한 규칙 적용

사용자 입력뿐 아니라 AI가 생성한 단어 역시 동일한 `Validator`를 거치도록 구현했습니다.

이를 통해 AI도 게임 규칙을 위반하면 실수를 기록하며, 사용자와 동일한 규칙을 적용받도록 설계했습니다.

---

## 역할 분리

게임 진행(Game), 상태 관리(GameState), 규칙 검증(Validator), OpenAI 통신(OpenAIClient)을 각각 독립된 모듈로 분리했습니다.

이를 통해 각 클래스가 하나의 책임만 수행하도록 구성했으며, 유지보수성과 확장성을 높이고자 했습니다.

---

## 한계 및 개선 방향

현재 프로젝트는 표준국어대사전을 직접 구축하지 않고 OpenAI를 이용해 단어를 검증합니다.

따라서 드물게 잘못된 판정이 발생할 가능성이 있으며, 실제 서비스에서는 표준국어대사전 데이터베이스를 직접 구축하거나 공식 사전 API를 활용하는 방식이 더 적합하다고 생각합니다.

또한 현재는 콘솔 환경을 대상으로 구현했지만, 향후 GUI 또는 웹 환경으로 확장하여 동일한 게임 엔진을 재사용할 수 있도록 개선할 수 있습니다.
